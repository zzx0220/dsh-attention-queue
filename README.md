# dsh-attention-queue

English | [简体中文](./README.zh.md)

Generated by an AI agent (DeepSeek Harness, `deepseek-flash`).

A persistent attention queue pinned above the session list in DeepSeek Harness Web. It answers
one question across every workspace: **which sessions need me?**

Each entry is classified as one of two states:

- **Unseen** — the run finished while you were viewing a different session.
- **Needs reply** — you have opened it, and it is still waiting on an approval, a plan review,
  or a question.

Interface copy follows the host application's language: English when the app runs in English,
Chinese when it runs in Chinese.

The plugin is pure front-end: no build step and no runtime dependencies. `client.js` is a
hand-written `ModuleLoader` bundle that takes `react` from the host.

## Installation

Requirements: the DSH CLI (`dsh`), `pnpm`, and `git` (used by the git-dependency install).

The same command works on macOS, Linux and Windows:

```sh
dsh plugin --profile desktop add github:zzx0220/dsh-attention-queue
```

Restart DeepSeek Harness afterwards; the client bundle is composed at startup. The queue card
appears at the top of the sidebar once the plugin is active.

### Verifying registration

`dsh plugin` forwards its arguments to pnpm, so fetching the package and registering it in the
profile's bundle list are separate operations. Confirm the registration once:

```sh
dsh --profile desktop --dump-config | grep attention-queue
```

Any output means the bundle is registered. If there is none, add `"dsh-attention-queue"` to the
`dsh.profile.bundles` array in `~/.dsh/profiles/desktop/package.json`, then restart.

### Upgrading

A git dependency is pinned to the commit it was installed from and does not follow the
repository. Request a new version explicitly:

```sh
dsh plugin --profile desktop add github:zzx0220/dsh-attention-queue#v0.1.1
```

### Uninstalling

```sh
dsh plugin --profile desktop remove dsh-attention-queue
```

Then remove the corresponding entry from `dsh.profile.bundles` and restart.

## Why another indicator

The shipped UI already tracks the three facts this queue is built from, but it does not
accumulate them:

| Fact | Source (DSH Web internal store) |
| --- | --- |
| A session is running or stopped | `useSessionStatus` → `running` |
| A session is blocked on you | `pendingInteraction.kind` = `approval` / `plan-review` / `question` |
| A run finished unseen | `completionUnread` |

`completionUnread` is an in-memory `Set` of the page, so a reload forgets it, and the states are
scattered as small dots inside each workspace group. This plugin maintains its own **persistent**
queue and renders it as a single pinned card.

## State transitions

- A session moves from `running` to stopped while you are viewing a different session → enters
  **Unseen**.
- A `pendingInteraction` appears while you are not viewing that session → enters **Needs reply**
  directly, which has the highest priority.
- Opening an **Unseen** entry keeps the row in the list and changes its subtitle to *viewing*:
  an entry should not disappear while it is being read.
- Resolution happens after you leave the session. If it is still waiting on an approval, a
  question or a plan review, it becomes **Needs reply**; otherwise it is removed.
- When the session runs again (you replied), the entry is removed immediately.
- Hovering a row exposes *keep as needs reply* and *mark done*, which cover the cases automatic
  detection cannot resolve — for example an assistant that asks a question in plain text.
- On restart, sessions whose `updatedAt` is newer than the last time you left the client, and
  which were never dismissed, are restored as **Unseen**.

## Implementation notes

- **Mount point**: `shell.overlay`, a list-kind root-scope slot intended for badges, toasts and
  status strips. It is click-through by default, and each entry opts into pointer events.
  `sidebar.workspaces` is a **single**-occupant slot, so using it would shadow the shipped
  session list.
- **Anchor**: the bounding box of `[class*="_regionArea"]` is measured to place the card directly
  above the session region. When that element cannot be found, the card falls back to the frame
  corner.
- **Navigation**: `ctx.uiWorkspace.openSession(id)`, the same path the shipped fork-and-jump uses.
- **Notifications**: `new Notification`, coalesced into one notification per batch over a 1.2 s
  window. Clicking the notification opens the session.

## Known limitations

- "Needs reply" relies on `pendingInteraction` plus manual marking. A question asked in plain
  assistant text is not detected automatically.
- The queue is stored in `localStorage` per origin. Multiple windows share it, and the last write
  wins.
- There is no end-to-end test. Verification means installing the plugin and completing a session
  to observe whether it enters the queue.
- The plugin depends on host internals: the `shell.overlay` mount point, `useSessionStatus` /
  `useSessions`, and the `_regionArea` class name are not stable APIs, and a minor DSH release
  may break them. After installing on a new machine, run the acceptance check: the card appears,
  a finished session enters the queue, clicking an entry navigates to it, and notifications fire.

## Development

```sh
node scripts/smoke.mjs
```

The script loads `client.js` with stubbed `window` / `localStorage` / `Notification` and drives
the state machine through its key transitions. It is the first regression check after any change.
`client.js` has no build step; restart the host to load a change.

For local iteration the working directory can also be linked into a profile as a `link:`
dependency, using the symlink approach described in earlier revisions.
